# ECR Channel Intelligence Card Template v2.0

## 定位与原则

Channel Card 是西班牙出海智能体的标准渠道判断单元，负责“索引 + 判断”；地区网点、成员明细和持续变化数据保存在底层数据库或专项事实卡中，通过链接调用。

- 原 8 大渠道分类保持不变，同一公司允许拥有多个一级渠道标签。
- 一级渠道、Vertical、Business Model 分层记录，不互相替代。
- 已有同义内容合并到九段结构，不重复堆字段。
- 公开事实、Leon View、一线情报和待研究项必须明确区分。
- 没有证据的字段写“待研究/待核验”，不得补全式推测。

## 08 AI什么时候调用它｜AI Retrieval Rules

- 必须调用：哪些产品、渠道、地区、组织形式、进入方式或公司问题命中时调用。
- 联合调用：需要同时读取的产品画像、区域数据库、专项事实卡或其他 Channel Card。
- 不应调用：哪些问题不应由本卡回答。
- 输出边界：公开事实、Leon View、推测、待研究分别如何表达。
- 召回标签：一级渠道、Vertical、Business Model、地区、品牌/网络、进入方式、关键词。

AI 调用顺序：`产品输入 → Vertical 识别 → 原 8 大渠道多标签匹配 → Business Model 判断 → Channel Card → 区域/事实数据库 → Leon View 修正 → 进入建议`。

## 09 证据是什么｜Evidence & Confidence

- 信息可信度：高 / 中 / 低（说明口径）
- 关键断言可信度：对组织权责、区域强弱、进入路径等重要结论，可逐项附“来源 + 日期 + 可信度”。
- 最后核验：YYYY-MM-DD
- 公开来源：页面/报告名称、发布主体、链接、发布日期或访问日期
- Leon 一线来源：仅写可披露的来源类型与日期；敏感细节进入 Private Layer
- 口径冲突：并列保留，不强行统一
- 待研究清单：

动态数据必须带来源和核验日期；事实变化时更新底层事实卡，并同步修正本卡结论。
