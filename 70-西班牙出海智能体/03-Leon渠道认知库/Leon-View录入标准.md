# Leon View 录入标准

每条 Leon View 至少包含：判断对象、结论、适用条件、依据、反例或失效条件、信心等级、形成日期、最近复核日期。

必须区分：

- Leon 亲身经历
- 基于多个案例形成的经验规律
- 基于公开信息的分析
- 尚待验证的个人假设

未经 Leon 确认，不得把模型生成的推断写成 Leon View。

## 四层知识结构

渠道卡中的知识必须分层保存，不能混写：

1. `PUBLIC FACT`：公司官网、官方报告或可靠公开来源可核验的事实。
2. `FIELD INTELLIGENCE`：门店走访、采购反馈、展会交流和真实测试等一线信息。
3. `LEON VIEW`：Leon 基于亲历、多个案例或行业规律形成并确认的判断。
4. `MODEL ANALYSIS`：智能体基于前述材料得出的推演，只能标为分析或“待 Leon 确认”。

对外回答时，事实可以直接陈述；一线情报需说明时间和可信度；Leon View 要明确是 Leon 的判断；模型分析不得借 Leon 名义输出。

## 认知类比的录入规则

“老外版华人批发商”属于 Leon 的解释性框架，不是公司官方分类。录入时至少包含：

- 类比共同点：为什么这个比喻能帮助中国企业理解。
- 关键差异：哪些治理、合同、采购或门店关系不能类推。
- 使用场景：适合解释渠道生态，不用于法律主体、商业条件或事实字段。
- 失效条件：当公司实质为直营连锁、纯进口商或无会员网络时，不使用该类比。
