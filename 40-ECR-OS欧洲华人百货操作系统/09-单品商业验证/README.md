# 09-单品商业验证

## 定位

这是 ECR-OS 从“方法”进入“真实市场验证”的执行层。

目标不是一次把系统做完整，而是从一个真实产品开始，在西班牙华人百货渠道完成小规模测试，验证产品、渠道、价格、终端营销和消费者反馈，并把有效方法沉淀成可复用工具与 SOP。

## 核心原则

1. 先跑通一个产品，再复制第二个产品。
2. 先做真实业务，再建设工具；业务走一步，工具跟一步。
3. 能人工验证的先人工验证，重复出现的工作再标准化和自动化。
4. 每个项目都必须留下数据、结论、失败原因和可复用资产。
5. Leon 负责选品、渠道、人际沟通和关键判断；AI/Codex 负责研究、整理、自动化和工程实现；GitHub 负责沉淀。

## 与现有目录的关系

- `02-供应链管理`：供应链方法和标准
- `03-产品池`：候选产品池
- `04-门店升级方案`：终端陈列和体验方案
- `05-网站与数字系统`：消费者网站、二维码、数据系统
- `06-数字化营销`：内容和引流
- `07-运营SOP`：跑通后沉淀标准流程
- `08-数据卡与报表`：统一指标与复盘数据
- `60-商业机会库`：外部企业、联系人和合作机会资源池

本目录不替代这些模块，而是把它们围绕一个真实产品串起来。

## 项目结构

每个真实测试产品建立独立项目，例如：

- `001-首个产品验证`
- `002-第二产品验证`

每个项目按同一套阶段推进：

1. 产品定义
2. 供应商与合作模式
3. 市场与竞品
4. 合规与风险
5. 价格与利润模型
6. 种子门店
7. 首批测试
8. 终端营销物料
9. 产品落地页与二维码
10. 销售与扫码数据
11. 门店和消费者反馈
12. 复盘与 GO / ITERATE / STOP 决策

## 当前任务

先建立 `001-首个产品验证`。

第一阶段不追求大规模铺货，也不追求完整平台，目标是用最小成本验证：

> 能不能找到一个值得卖的产品，并让真实的西班牙华人百货门店愿意测试，最终产生消费者购买和补货。
