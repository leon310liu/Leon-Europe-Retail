## 一、战略定位

Leon Resource Map 不是通讯录，也不是一张静态的“认识谁”清单。

它要逐步建设成一套可查询、可验证、可评价、可调用的真实欧洲落地资源网络，最终成为 Leon GTM AI 的核心能力之一。

2030 目标：

> 当中国企业进入欧洲时，Leon 不仅知道怎么做，还能从已经研究、联系、验证和合作过的资源网络中，找到当前场景下值得调用的合作方。

资源库建设服务于三个结果：

1. 为 Leon 和团队提供真实的欧洲落地执行网络。
2. 把个人关系、合作经验和避坑认知转化为组织资产。
3. 为 Leon GTM AI 未来的资源匹配、风险判断和行动建议提供可追溯数据。

## 三、Leon Resource Level 统一等级

资源等级表示的是 Leon 与该资源之间的实际关系和验证深度，不是对方的市场规模或知名度。

| 等级 | 名称 | 最低认定标准 | 可调用边界 |
|---|---|---|---|
| L0 | 发现 | 已获得基础线索，尚未完成系统研究 | 只可作为待研究线索，不得对外推荐 |
| L1 | 已研究 | 已核对基本信息、业务范围与公开信誉信号 | 可进入候选池，不等于已建立关系 |
| L2 | 已建立联系 | 已与可确认的联系人建立双向沟通 | 可用于需求初询，不代表能力已验证 |
| L3 | 已验证 | 已通过尽调、样例、转介或小规模测试验证核心能力 | 可在清晰说明验证范围后进入项目候选 |
| L4 | 已合作 | Leon 或团队已有真实付费或业务合作经验，并完成复盘 | 可结合实际合作边界优先调用 |
| L5 | 战略资源 | 经过多次合作验证，关系稳定，价值高且有长期共建意愿 | 可作为核心合作伙伴纳入战略项目 |

管理原则：

- 等级只能根据证据逐级提升，不因个人熟悉感或对方品牌知名度跳级。
- 每次升级必须记录时间、依据与责任人。
- 资源状态与资源等级分开管理；已合作资源也可因为失效、风险或关系中断被标记为暂停调用。
- 任何降级、暂停或黑名单处理都必须保留原因与历史记录。

## 四、资源体系三层架构

```text
Resource Database
资源发现、分类、基础数据、联系记录、证据与状态
        ↓
Leon Verified Network
经过 Leon 及团队联系、验证、合作和复盘的 L2–L5 真实关系网络
        ↓
AI Resource Intelligence
基于需求、国家、品类、阶段、预算、风险与 Leon View 进行资源匹配和决策支持
```

### Layer 1｜Resource Database

解决“有哪些资源、数据是否完整、信息来自哪里”。

输出：统一资源卡、标签体系、联系与验证日志、数据时效和证据链。

### Layer 2｜Leon Verified Network

解决“谁真正值得联系、谁的哪项能力已被验证”。

输出：L2–L5 关系网络、能力证据、合作复盘、Leon View 与风险提示。

### Layer 3｜AI Resource Intelligence

解决“在某个具体出海场景中，应该调用哪些资源、以什么顺序、需要防什么风险”。

输出：候选资源组合、适配原因、不适用边界、风险警示、建议验证动作与人工复核节点。

AI 不能因“已入库”就将某资源表述为 Leon 推荐；必须同时展示资源等级、数据时效、验证边界与风险信息。

## 五、统一资源卡字段

每个资源建议使用独立的 Resource ID，格式为：

```text
R大类.子类-国家/区域代码-流水号
```

例如：`R04.04-ES-0001`。该示例只用于说明编号结构，不代表真实资源。

### A. 身份与分类

- Resource ID
- 资源名称 / 法定名称
- 资源库大类与子类
- 国家、区域、城市
- 服务语言
- 业务范围、品类与场景标签

### B. 能力与服务

- 核心能力 / 产品 / 服务
- 覆盖市场与交付范围
- 目标客户与最低合作条件
- 价格 / 费用模式（如可获得）
- 服务能力证据

### C. 关系与验证

- Leon Resource Level
- 当前状态：待研究 / 可联系 / 验证中 / 可调用 / 暂停 / 失效
- 联系人与关系归属
- 首次发现、最近联系、最近验证日期
- 联系、验证与合作记录
- 负责人与下一步动作

### D. 证据与数据治理

- 信息来源与可追溯链接 / 文档
- 信息获取日期
- 数据可见范围与隐私级别
- 数据完整度与可信度
- 下次复核日期
- 历史变更记录

## 六、Leon View 沉淀标准

重要资源不能只有公开信息和联系方式，必须逐步沉淀 Leon View。Leon View 是对经验、证据和场景边界的结构化判断，不是无依据的主观印象。

### Leon View 模板

```text
【一句话判断】

【适用场景】
- 适合什么国家、品类、企业阶段和项目规模？

【不适用场景】
- 什么情况下不应该选择该资源？

【核心优势】
- 已被什么证据或经验证明？

【风险 / 坑】
- 容易发生什么误判、隐性成本、交付风险或合作问题？

【合作体验】
- 响应、专业度、交付、价格、沟通与问题处理表现如何？
- 未合作时必须明确标注“尚无实际合作证据”。

【推荐等级】
- A 优先推荐 / B 可作为候选 / C 谨慎使用 / D 不建议
- 推荐等级必须附带适用前提，不得脱离场景给出绝对结论。

【判断依据】
- 来源、验证 / 合作记录、记录人、记录日期。

【有效期与下次复核】
```

推荐等级与 Resource Level 不是一件事：Resource Level 表示关系与验证深度；推荐等级表示对某个具体场景的适配性判断。

## 七、数据原则与边界

1. **真实性优先**：不得把搜索线索写成已验证事实，不得虚构联系人、关系或合作经验。
2. **证据优先**：每个关键判断都要尽量回到公开资料、沟通纪要、合同、交付成果或复盘记录。
3. **事实与判断分离**：客观数据、对方自述、第三方评价和 Leon View 必须分开存储。
4. **时效可见**：资源、人员、价格和政策都会变化；调用前必须查看最近验证时间。
5. **场景化推荐**：没有绝对的“最好资源”，只有特定国家、品类、阶段、预算与风险偏好下的更好匹配。
6. **隐私与权限**：个人联系方式、合同、价格与负面经验必须分级管理，不得默认用于公开内容。
7. **人工最终负责**：AI 可以检索、比较和生成候选建议，但重要项目的最终资源选择由 Leon 或授权负责人确认。

## 八、建设顺序

### Phase 1｜建库

- 确定十大资源库与标签体系。
- 建立统一资源卡、Resource ID 与证据标准。
- 优先录入 Leon 已有的真实联系、历史合作和已研究资源。

### Phase 2｜验证网络

- 按战略优先级对 L0–L1 资源展开联系和能力验证。
- 对 L3–L5 资源形成 Leon View 与合作复盘。
- 持续清理过期、失效和高风险资源。

### Phase 3｜AI 资源智能

- 将资源与产品、国家、渠道、合规要求及项目阶段建立关联。
- 建立资源检索、匹配、组合、风险提示与可解释推荐机制。
- 通过真实项目结果反馈持续修正资源评价和匹配逻辑。

## 九、当前版本边界

V0.1 只确认：

- 十大资源库的总体框架。
- Leon Resource Level L0–L5。
- Resource Database → Leon Verified Network → AI Resource Intelligence 三层架构。
- 统一资源卡的基础字段。
- 重要资源的 Leon View 沉淀标准。
- 资源数据的真实性、证据、时效、隐私与 AI 调用边界。

V0.1 不包含：

- 任何未经确认的具体企业、机构、门店、服务商、联系人或合作关系。
- 任何虚构的合作评价、推荐等级或 Leon View。
- 十大资源库的数量 KPI。KPI 应在完成首轮基线盘点后另行制定。

---

**核心判断：**

> Leon Resource Map 的价值不在于“库里有多少名字”，而在于有多少资源已经被真实研究、建立关系、验证、合作和复盘，并能够在正确的欧洲落地场景中被 Leon GTM AI 安全调用。
